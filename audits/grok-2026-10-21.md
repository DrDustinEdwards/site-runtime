## Threat model (STRIDE)

The package is what every site inherits for headers, CSP, the CSP report sink, a capped body read, HTML escaping, secret compare, Cloudflare Access (request JWT and the SaaS OIDC login), the members rules, and one rate limiter. It holds no database of its own. A site imports it. The thing it can lose is a check that says a weak response is fine, a login that accepts a bad token, or a token a workflow can use to push.

Who can call it: any site that imports the modules, anyone who runs `check-security-headers` against URLs they choose, and GitHub Actions on `pull_request`, push to `main`, a `v*` tag, and `workflow_dispatch`.

Entry points:

- Library functions. No HTTP server lives here. A site calls `receiveCspReport`, `verifyAccessRequest`, `finishSignIn`, `limit`, and `applyHeaderSet`.
- CLI: `bin/check-security-headers.mjs`.
- Workflows: `ci.yml` (pull request and push to main), `ai-author.yml` (same), `pr-footer.yml` (pull request opened, reopened, edited, and dispatch), `code-map.yml` (push to main and dispatch), `bump-consumers.yml` (tag `v*` and dispatch).
- No MCP tool, cron, queue, or webhook in this repo. `access-login.mjs` is the login those MCP servers call.

Where trust changes:

- A response's headers are untrusted until `checkSecurityHeaders` grades them. The grade is the gate (SR-1, SR-3).
- CSP report bodies are untrusted. They are capped, trimmed, and logged. They are not stored and not sent to a model.
- `Cf-Access-Jwt-Assertion`, the `CF_Authorization` cookie, and the OIDC code are untrusted until `verifyJwt` checks the signature.
- `ACCESS_TEAM_DOMAIN` is trusted as configuration and becomes the host that receives the client secret (SR-8).
- `extraDirectives` is trusted as site configuration and is copied into the policy after the script-source refusal (SR-1).
- Caller workflow inputs in the pinned devkit code-map run as shell in a job whose token can push (SR-2).

Spoofing: RS256 is pinned, `alg` is not taken from a place the signature can swap, issuer and audience are exact. An empty secret matches nothing.
Tampering: `main` is unprotected (SR-2). The members rules refuse a change at or above the actor's layer, and refuse a grant the actor does not hold.
Repudiation: `auditRow` is a pure function. The app has to write it. The package cannot force the batch.
Information disclosure: CSP logs drop the query string. Rate-limit logs drop the last key segment. `finishSignIn` refusal reasons do not include the token or the secret. The code-map job still has the GitHub token in the measure steps (SR-2).
Denial of service: report bodies stop at 16 KB, violations at 10, key refetch at 30 seconds on the Access certs path. Jobs set `timeout-minutes`.
Elevation: `extraDirectives` and a hand-written policy can allow inline script while the check stays green (SR-1). The Primary Owner comes from configuration, and a row cannot claim that layer.

## Findings

### SR-1 MAJOR, security, confirmed by running

Files: `check.mjs` lines 84-123, `csp.mjs` lines 127-152.

`checkSecurityHeaders` is the grade a site's CI and `bin/check-security-headers.mjs` use. Against `STANDARD_SECURITY_HEADERS` plus a policy, these inputs produced an empty failure list:

- `frame-ancestors *`
- `frame-ancestors https://evil.example`
- `script-src-elem 'unsafe-inline'`
- `worker-src 'unsafe-eval'`
- `form-action *`, and a policy with no `form-action` at all
- the same standard set with those policies

`form-action` does not fall back to `default-src`. A policy the check calls clean can post forms anywhere. `frame-ancestors` is only required to be present (`check.mjs` line 108), so any origin may frame the page. `script-src-elem` is what a browser uses for `<script>` when that directive is present, and `worker-src` is what it uses for workers. The check reads `script-src` only.

The builder refuses `*`, a bare scheme, and `'unsafe-inline'` / `'unsafe-eval'` on `sources.script` (lines 127-133). `extraDirectives` are appended after that loop and are only rejected when the directive text is empty (`csp.mjs` line 150, `buildPolicy`). This call is accepted and the check then reports no failures:

```js
buildContentSecurityPolicy({
  reportUri: "/r",
  extraDirectives: ["script-src-elem 'unsafe-inline'", "script-src-elem https://evil.example"],
})
```

The policy contains `script-src 'self'` and then `script-src-elem 'unsafe-inline'`. A browser runs the inline script. The test "every policy the builder writes passes the header check" does not include this input, so it stays green.

Path: a site adds a directive through `extraDirectives`, or ships a CSP the builder did not write, and both the unit check and the live CLI exit 0. Inline script runs, or the page can be framed, or a form posts off-origin.

Smallest fix: in the builder, refuse `script-src-elem`, `script-src-attr`, and `worker-src` values that the script rules already refuse, and refuse an `extraDirectives` entry that redefines `script-src`, `form-action`, or `frame-ancestors`. In the check, require `form-action` to be `'self'`, `frame-ancestors` to be `'none'` or `'self'`, and apply the script rules to `script-src-elem`, `script-src-attr`, and `worker-src`.

`connect-src` and `img-src` may be a bare scheme. `csp.test.mjs` locks that in ("only script sources are held to the script rules"). A site that lists `connect: ["https:"]` gets a policy the check accepts, and the browser may send requests anywhere. That one is the documented choice. It is not part of this finding. It is the same shape, and the check will not catch it.

### SR-2 MAJOR, supply chain, confirmed by reading and by the API

`main` is not protected. Rulesets are empty. Secret scanning and push protection are on. Dependabot security updates are off.

`.github/workflows/code-map.yml` grants the called job `contents: write` and sets `coverage-command` to the test suite and `install` to `npm i --no-save typescript@5.9.3`. The pinned devkit workflow (`27e0a1ca`, tag `v0.7.0`) puts `contents: write` on the whole `map` job. Install runs `bash -c "$INSTALL"`. Measure coverage runs `bash -c "$COVERAGE"`. `persist-credentials: false` in that workflow does not remove `GITHUB_TOKEN` from the step environment. The publish step is the one that names the token. This was not executed on a live runner. The confidence is the two workflow files plus GitHub's documented default environment.

Path: a push to `main` runs the test suite and `npm i` of typescript with a token that can push. `main` has no protection, so that step can push to `main`. typescript is pinned to `5.9.3`, which limits the install to that version's scripts. The tests are this repo's own files. The token is still in their environment.

The same unprotected branch meets `.github/workflows/bump-consumers.yml`. A push of a `v*` tag runs the workflow file in that tag commit and passes `secrets.RENOVATE_TRIGGER_TOKEN`. The header of the called workflow describes that token as a fine-grained PAT with contents read and issues write on the owner's repositories. A tag whose workflow file prints the secret discloses a credential that reaches past this repo. Pushing that tag takes write access. Write access is also what unprotected `main` already allows.

Smallest fix: protect `main` (require `ci`, block force-push) and protect tags. For the map, take a devkit sha that measures with `contents: read` and publishes from an artifact. Until that sha exists, the write and the test command sit in one job because the called workflow is one job.

### SR-3 MINOR, security, confirmed by running and by reading

`checkSecurityHeaders` and `runOshpSuite` grade the same header and do not agree. The CLI (`bin/check-security-headers.mjs` lines 29-35) runs only the check.

Probe, same standard set, empty failure list from the check:

- `Strict-Transport-Security: max-age=63072000` with `includeSubDomains` removed. The standard value, and the OSHP suite at `oshp-tests-suite.yml` lines 18-19, require `max-age=63072000; includeSubDomains` or the same with `; preload`.
- `X-Frame-Options: sameorigin` while the standard is `deny`. The suite at line 30 allows `deny` and `DENY` only. The check's special case (`check.mjs` lines 71-72) allows `sameorigin` in any case, and it does that even when the floor value is `deny`.

The README defines the check as "HSTS at least the set's age" and "framing refused", and the code matches those sentences. The suite in the same package is the stricter oracle, and the command a site points at a live URL never runs it.

The suite's CSP case (`oshp-tests-suite.yml` line 52) is `ShouldNotContainSubstring "unsafe"`. `buildContentSecurityPolicy({ reportUri: "/csp", styleAttributesInline: true })` writes `style-src-attr 'unsafe-inline'`, which contains that substring. The README tells a site to turn that option on for style attributes and to run the suite. The default builder output omits it, which is why `test/oshp-suite.test.mjs` expects the CSP case to pass. A site that follows both instructions fails the CSP case for a directive the package offers, and a real `script-src 'unsafe-inline'` fails the same case. The suite can no longer tell them apart.

Smallest fix: teach the check to require `includeSubDomains` when the floor has it, and to require `X-Frame-Options` to match the floor. Point the CLI at both grades, or drop the suite assertion that treats every `unsafe` as a script failure and assert the script directives the check already names.

### SR-4 MINOR, tests, confirmed by running

`test/oshp-suite.test.mjs` `readSuite` (lines 21-37) matches lines with `$`. The file in git is LF (`git ls-files --eol` says `i/lf`). This working copy is CRLF (`w/crlf`). The line loop then sees a trailing CR, the `$` anchor misses, and the reader returns 0 cases. The count of `name:` lines is 17. `npm test` fails those four tests. `runOshpSuite` throws "the suite has no test cases" rather than passing an empty run. CI on ubuntu is green, so the committed LF file parses there.

Path: a Windows checkout, which is where this audit ran, never executes the OSHP oracle. A refresh or an editor that writes CRLF does the same on ubuntu, and CI goes red only after the push. It does not go green.

Smallest fix: strip a trailing CR in `readSuite` before matching. Add a test whose fixture is the suite file with CR restored.

### SR-5 MINOR, supply chain, confirmed by reading

Moving that tag changes the bin the check runs without a workflow-sha change.

### SR-6 MINOR, data integrity, confirmed by reading

`update-owasp.mjs` fetches three files from `https://raw.githubusercontent.com/OWASP/www-project-secure-headers/master` with no commit pin (line 22), then `writeFile`s `owasp-headers.mjs`, `oshp-tests-suite.yml`, and `README.md` one after another (lines 68-81). The header says a failed refresh never leaves a half-written set. A throw before the first write does that. A crash or a throw after the first write leaves the header module and the suite disagreeing. The script is not in CI. A person runs it and reviews the diff. The unpinned `master` is what that diff is made from.

### SR-7 MINOR, authorization, confirmed by reading

`members/index.mjs` `allowList` (lines 223-225) keeps every active, unexpired row. It does not ask the catalog whether `row.title` exists. `resolveActor` returns null for an unknown title (line 99), so the app's own permission check refuses that person. The Access allow list is a different gate. The README says the list is the emails the app's Access group should hold.

Path: a row with status `active`, a future `end_date`, and a title that is not in the catalog is returned by `allowList` and omitted by `resolveActor`. If the sync writes that list into Access, the person can pass Access and only then be refused by the app. A route that trusts Access alone admits them.

`test/members.test.mjs` "the allow list is every active, unexpired row" uses known titles, so it stays green.

Smallest fix: drop a row whose title is not in the catalog.

### SR-8 MINOR, security, confirmed by reading

`access-login.mjs` `accessSaas` (lines 27-33) builds the issuer from `ACCESS_TEAM_DOMAIN` plus the client id. It checks that the three settings are non-empty. It does not require the host to be a `cloudflareaccess.com` host. `finishSignIn` (lines 168-178) POSTs `client_secret` to `saas.tokenUrl`. `access.mjs` `accessIssuer` (lines 31-37) similarly accepts any host of letters, digits, dots, and hyphens, and `accessKeys` fetches `https://<host>/cdn-cgi/access/certs` and trusts those keys.

Path: `ACCESS_TEAM_DOMAIN=https://attacker.example` (a typo, or a value that was not the dashboard host) makes every sign-in post the SaaS client secret to that host, and makes `verifyAccessRequest` trust JWTs signed by that host's keys. The settings are the site's env, not request input. A request cannot set them through this package.

Smallest fix: require the host to end with `.cloudflareaccess.com` in both constructors, and refuse anything else the way a missing setting already refuses.

### SR-9 MINOR, data integrity, confirmed by reading

This repo's `code-map.yml` does not pass `mutation-command` or `mutation-artifacts`. The pinned workflow's "Read the kept mutation run" step treats any failed `git fetch` or `git cat-file` of `mutation.json` as "no kept run", and the publish step force-pushes a fresh tree. A run that could not read an existing `mutation.json` deletes it. The published map for this commit has `"mutation": null`, which matches a repo that has not stored a mutation run. The hole is the next run after one exists.

Smallest fix: the same one as in devkit. If the branch exists and the file cannot be read, fail the job. This caller picks up that sha.

## Area by area

### 1. Security

Credential table:

| Credential | Where it lives | Who can read it | What a leak opens | Rotation |
| --- | --- | --- | --- | --- |
| `ACCESS_SAAS_CLIENT_SECRET` | The caller's env. Not in this repo. | `finishSignIn`, which posts it to the token URL | The SaaS app's token endpoint, together with the client id | The Access dashboard. This package has no rotation path. |
| `ACCESS_SAAS_CLIENT_ID`, `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD` | The caller's env | The login and the request check | They name the app. They are not the secret. A wrong host is SR-8. | The caller. |
| Access request JWT and `CF_Authorization` | The request | `verifyAccessRequest` | Nothing until the signature, issuer, and audience check pass. A forged token is a refusal. | Access issues a new token per session. |
| `GITHUB_TOKEN` | The code-map job | Every step of that job (SR-2) | `contents: write` on this repo | GitHub issues a new token per job. |
| `RENOVATE_TRIGGER_TOKEN` | Repository secret, passed by name | The bump-consumers job, including a tag commit's workflow file (SR-2) | Contents read and issues write on the repos that PAT can see | The caller rotates the PAT. |
| `CLOUDFLARE_API_TOKEN` | Not used. This repo does not deploy. | | | |

Checked and clean, apart from SR-1, SR-2, SR-3, and SR-8:

- Injection. Header values and CSP sources are rejected when they contain a space, semicolon, or comma. The nonce must match a base64 shape before it is placed in `'nonce-...'`. SQL in the rate limiter is bound, and the table SQL is a constant. The CLI passes URLs as fetch arguments, not as a shell string.
- HTML. `escapeHtml` replaces `& < > " '` . The tests cover a quote used to break out of an attribute. The README says it is not an encoder for unquoted attributes, `javascript:` URLs, or the inside of `<script>` and `<style>`.
- API. No server. The report receiver answers 204 to POST, 405 otherwise, and reflects `Access-Control-Allow-Origin` only when `Origin` equals the one `allowOrigin`.
- Authentication. `verifyJwt` requires three segments, `alg === "RS256"`, a string `kid`, an RSA key from the caller, a valid signature over `header.payload`, exact `iss`, `aud` equal to the audience or one entry of an array, a numeric `exp`, and `nbf` when present. Skew is 60 seconds. `alg: none` and a non-RSA key are refusals. The key import passes `kty`, `n`, and `e` only. The plant tests name each of those refusals.
- Sessions and OAuth. `newSignIn` makes a 32-byte verifier and a nonce. `authorizationUrl` sends S256 and does not put the verifier in the query. `finishSignIn` sends the verifier, requires the nonce to match, refuses `email_verified === false`, and requires an email. State storage is documented as the OAuth provider's job, not this module's.
- Authorization. Members: layer 0 comes only from `PRIMARY_OWNER_EMAIL`. A row with that email does not lower them. A row cannot use a layer-0 title. `checkChange` refuses the Primary Owner's email, a peer, a wider bundle, a missing one-line reason, and an end date past the default. Owners hold every permission. SR-7 is the allow-list gap.
- CSRF, replay, rate limits. The login's state and PKCE are the caller's to store once. The rate limiter counts in one synchronous SQL block, writes nothing when a rule is spent, and requires `onUnavailable` with no default. `ipKey` uses `CF-Connecting-IP`, which Cloudflare sets. A missing header shares `prefix:anon`, which limits harder. `limitedResponse` is 429 or 503, never 2xx.
- Crypto. `safeEqual` hashes both sides to 32 bytes, compares with `timingSafeEqual` when the runtime has it and with a full XOR otherwise, and rejects a non-string or an empty side. `generateNonce` is 16 random bytes. `scriptHash` is SHA-256 of the script text.
- Headers. The standard set is OSHP's recommended values minus the four skipped, each skip with a reason. Overrides need a reason of at least 12 characters, cannot restate the standard, and cannot delete a header the standard does not send. `applyHeaderSet` overwrites by default. Report-Only alone fails the check. `object-src` must be exactly `'none'`. `base-uri` must be `'none'` or `'self'` and does not fall back.

### 3. Secrets and privacy

No secret in the tree or in the history search. CSP logs keep origin and path, drop the query, and cap the directive at 64 characters. A session id that lives in the path would be logged. The README says the path is kept. Rate-limit logs keep the key's bucket and drop the last segment. Privacy claims in the README match the code that was read.

### 4. Data integrity

SR-6 and SR-9. Also checked:

- `readCapped` returns null when the byte count passes the ceiling, cancels the stream, and throws if the stream errors. It does not return a truncated body. A lying `Content-Length` is ignored by the counter. The report receiver also returns 204 when the declared length is already over 16 KB, before the read.
- `hitRules` checks every rule before any insert. A spent rule writes nothing. The insert is `ON CONFLICT` on the primary key, so a window change replaces that one row rather than appending.
- `auditRow` sets `cloudflare: "pending"`. The package does not write the row. A caller that skips it has no audit. That limit is in the README.
- `reset` of a database is not this package. There is no migration.
- Logout headers are a separate set. They are not applied by `applyHeaderSet` unless the caller passes them.

### 5. Correctness

SR-1, SR-3, SR-4, SR-7. Also checked and behaving as the tests describe:

- HSTS age is parsed from `max-age=`. A floor with no max-age wants one year. That special case is tested.
- Referrer-Policy allows `no-referrer`, `same-origin`, `strict-origin`, and `strict-origin-when-cross-origin` only.
- Permissions-Policy requires every feature the floor denies with `feature=()` to be denied. A response may deny more.
- Other standard headers must equal the floor, ignoring case and outer space.
- `parsePolicy` keeps the first of a repeated directive.
- Expiry is valid through the UTC end date and expired at the next midnight. The review opens 21 days before. Both boundaries are tested.
- `defaultEndDate` picks the next term end and throws when the owner has not entered a future one.
- `matchRule` decodes once, collapses slashes, drops a trailing slash, and lower-cases. `/LOGIN`, `/login///`, and `/%4cogin` match `/login`. A prefix does not match a longer segment name (`/api/auth` does not match `/api/authors`). The tests cover that.
- `email_verified` must not be false. A missing claim is accepted. The README says "must not be false", so a missing claim is the documented rule.
- `safeEqual` does not treat composed and decomposed `é` as equal. The test locks that in.
- `escapeHtml` does not escape an em dash, a backtick, or a slash. The README lists the five characters.

### 6. Reliability

- `accessKeys` throws when the certs endpoint fails, returns a non-OK status, or has no `keys` array. An outage is not a refusal. A kid miss refetches at most once per 30 seconds. Both are plant-tested.
- `remoteKeys`, used by the login, returns undefined on a failed fetch instead of throwing. `verifyJwt` then refuses `unknown-key`. A JWKS outage shuts the door. It does not admit anyone. There is no cooldown on that path. A bad code never reaches it. A good code with an unknown kid refetches twice (cached, then fresh). That is one sign-in, not a public loop.
- `limit` turns a missing binding or a thrown `hit` into `status: "unavailable"` and logs the bucket. `mustStop` refuses only when the caller passed `"refuse"`. `"allow"` is an explicit choice and still logs.
- The report receiver's `allow` is awaited before the body. A throw from `allow` becomes a Worker error, which is a status browsers retry. The package's own limiter returns a verdict rather than throwing, once the site uses it.
- `code-map.yml` concurrency does not cancel an in-flight run. Two pushes can still race the force-push. The later finishing job wins.
- Job timeouts: ci and the called checks are 5 minutes in the callers that set one. `ci.yml` sets 5. The called workflows set their own.

### 7. Performance and cost

No D1 query, so there is no D1 `EXPLAIN`. The rate limiter's per-hit statement, on `node:sqlite`:

`SELECT window_index, count FROM rate_window WHERE window_seconds = ?` plans as `SEARCH rate_window USING INTEGER PRIMARY KEY`.

The alarm's `DELETE` plans as `SCAN rate_window`. The table has one row per window length. A site's rules are a handful of rows. The scan is the alarm, not the request.

One allowed request is one Durable Object call, one primary-key read, and one write, which is the cost the README states. A refused request does not write. One CSP report reads at most 16 KB and logs at most 10 lines. One login is one token POST and, on a cold isolate, one JWKS fetch. The CLI fetches each URL once, with redirects off. There is no bundle of a Worker in this repo.

### 10. Architecture and simplicity

Real structure: a library of ES modules, no service. Sites import a path (`./csp`, `./access`, `./members`, `./rate-limit`). The Durable Object class is the one piece that must be exported from a Worker. `owasp-headers.mjs` and the suite YAML are generated. `update-owasp.mjs` is the only writer. The README's list of modules matches `package.json` exports.

Coupling: callers depend on refusal reason strings, the `::` free CLI text, and the header names. Tests lock the reason substrings and the CLI's `FAIL` lines. The members rules are pure so each app keeps its own tables. That boundary holds.

Over-engineering: the hand-rolled suite reader exists so the package has no YAML dependency. It is about 40 lines and it is also SR-4. I would keep it and strip CR. I would not add a YAML parser.

Under-engineering: the check does not grade the directives the builder treats as fixed (SR-1). Branch protection is absent (SR-2). A typecheck is absent.

Shared-package fit: this is the shared package. The Access login belonging here is what the README claims, and the code matches. Nothing here should move to devkit. The header grade should stay next to the builder so SR-1 can be fixed in one place.
